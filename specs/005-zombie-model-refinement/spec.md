# Feature Specification: 정교한 좀비 모델

**Feature Branch**: `005-zombie-model-refinement`

**Created**: 2026-07-27

**Status**: Draft

**Input**: User description: "좀비도 더 정교하게 만들어."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 위협 유형을 실루엣으로 즉시 구분한다 (Priority: P1)

플레이어는 전투 중 러너, 브루저, 리퍼를 색상이나 이름표 없이도 체형과 장비, 자세만으로 즉시 구분한다. 세 유형은 기존 단순 도형 조합을 벗어난 하나의 일관된 감염 세계관을 공유하면서도 역할별 위협이 명확하게 읽혀야 한다.

**Why this priority**: 빠른 표적 우선순위 판단은 거점 방어 전투의 핵심이며, 세 유형의 외형 차이가 이번 작업의 직접적인 가치다.

**Independent Test**: 세 모델을 같은 크기의 무채색 섬네일로 5초간 보여 주고 러너, 브루저, 리퍼를 각각 지목하게 한다.

**Acceptance Scenarios**:

1. **Given** 세 좀비가 같은 전투 화면에 있음, **When** 플레이어가 화면을 5초 이내로 확인함, **Then** 러너의 전방 기울기와 긴 다리, 브루저의 넓은 장갑 체형, 리퍼의 큰 칼날 팔을 서로 구분한다.
2. **Given** 색상과 발광을 제거한 세 실루엣, **When** 플레이어가 각 유형을 분류함, **Then** 세 유형 모두 고유한 역할로 식별된다.
3. **Given** 각 모델의 근접 프리뷰, **When** 플레이어가 세부 형상을 확인함, **Then** 감염 조직, 손상된 장비, 관절, 손발과 얼굴이 단순 기본 도형 조합이 아닌 의도적으로 조형된 형태로 보인다.

---

### User Story 2 - 정교한 외형이 기존 전투 판독성을 보존한다 (Priority: P1)

플레이어는 정교한 모델이 적용된 뒤에도 머리와 몸통을 안정적으로 조준하고, 피격·헤드샷·사망 및 리퍼의 특수 위협을 기존과 같은 규칙으로 읽는다.

**Why this priority**: 외형 개선이 조준 판정, 충돌, 이동, 사망 피드백을 바꾸면 기존 핵심 게임플레이를 훼손한다.

**Independent Test**: 각 유형을 생성해 기존 충돌 범위와 머리 판정선을 비교하고, 몸통 피격·헤드샷·사망·리퍼 공격 효과를 재생한다.

**Acceptance Scenarios**:

1. **Given** 정교한 모델이 연결된 좀비, **When** 좀비가 이동하고 공격함, **Then** 기존 게임플레이 루트의 위치·크기·충돌 범위와 이동 결과가 변하지 않는다.
2. **Given** 플레이어가 머리와 몸통을 각각 사격함, **When** 피격 판정이 발생함, **Then** 기존 헤드샷 배율과 피드백이 동일하게 적용된다.
3. **Given** 좀비가 피해를 받거나 사망함, **When** 피격·사망 효과가 재생됨, **Then** 모델 전체에 효과가 적용되고 다음 표적을 가리지 않는다.
4. **Given** 리퍼가 해태를 공격함, **When** 특수 공격 예고와 타격이 발생함, **Then** 리퍼의 외형과 기존 특수 효과가 함께 일반 좀비와 다른 위협을 전달한다.

---

### User Story 3 - 모델 문제가 있어도 전투를 계속한다 (Priority: P2)

개발자는 특정 좀비 모델이 누락되거나 불러오기 실패해도 해당 유형만 기존 절차형 외형으로 복구되어 전체 전투와 다른 좀비 유형은 정상적으로 유지되기를 원한다.

**Why this priority**: 제작 자산의 부분 실패가 플레이테스트나 빌드 전체를 중단시키지 않아야 한다.

**Independent Test**: 세 역할의 고해상도 모델 참조를 하나씩 제거한 뒤 각 역할을 반복 생성하고, 해당 역할만 기존 외형으로 복구되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 러너 모델만 누락됨, **When** 세 유형을 생성함, **Then** 러너만 기존 러너 외형을 사용하고 브루저와 리퍼는 정교한 모델을 사용한다.
2. **Given** 한 유형을 같은 게임플레이 루트에 반복 연결함, **When** 새 외형이 적용됨, **Then** 이전 외형과 세부 단계 그룹이 남지 않고 표현 루트가 하나만 존재한다.
3. **Given** 낮은 세부 단계 모델만 누락됨, **When** 해당 유형을 생성함, **Then** 고해상도 모델로 계속 표시되며 전투는 정상 진행된다.

### Edge Cases

- 한 역할 항목에 다른 역할의 모델이나 중복 자산 ID가 연결되면 검증 단계에서 거부한다.
- 모델 원본에 요구된 재질 영역이나 본 이름이 빠져 있으면 제작 계약 실패로 처리한다.
- 모델이 추가 자식 충돌체를 포함하더라도 런타임 게임플레이 충돌 판정에는 참여하지 않는다.
- 발광이나 색상을 구분할 수 없는 환경에서도 유형별 실루엣은 유지되어야 한다.
- 여러 좀비가 겹쳐도 브루저의 폭, 러너의 전진 자세, 리퍼의 칼날이 군중 외곽에서 읽혀야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 러너, 브루저, 리퍼 정확히 세 유형의 정교한 제작 모델을 제공해야 한다(MUST).
- **FR-002**: 각 유형은 재생성 가능한 편집 원본, 고세부 모델, 저세부 모델, 개별 프리뷰를 가져야 한다(MUST).
- **FR-003**: 시스템은 세 유형을 같은 카메라와 조명에서 비교하는 갤러리 프리뷰를 제공해야 한다(MUST).
- **FR-004**: 러너는 좁고 전방으로 기운 몸통, 긴 하체, 가벼운 손상 장비와 추격 방향을 강조하는 가시를 가져야 한다(MUST).
- **FR-005**: 브루저는 낮고 넓은 중심, 거대한 어깨와 팔, 겹친 장갑판과 비대칭 감염 덩어리를 가져야 한다(MUST).
- **FR-006**: 리퍼는 세 유형 중 가장 큰 세로 실루엣, 긴 칼날 팔, 분리된 머리 볏과 강한 특수 위협 중심부를 가져야 한다(MUST).
- **FR-007**: 세 유형은 같은 감염 세계관의 피부, 손상 장비, 암조직, 뼈와 발광 조직 언어를 공유해야 한다(MUST).
- **FR-008**: 각 고세부 모델은 16,000개를 초과하는 정점을 가져야 하며, 저세부 모델은 500개를 초과하고 대응 고세부 모델의 70% 미만이어야 한다(MUST).
- **FR-009**: 각 모델은 다섯 개의 의미 재질 영역을 모두 눈에 보이는 형상에 사용해야 한다(MUST).
- **FR-010**: 각 모델은 머리, 척추, 좌우 팔, 좌우 다리와 역할별 무기 또는 장갑을 찾을 수 있는 안정적인 계층 이름을 제공해야 한다(MUST).
- **FR-011**: 런타임은 기존 러너, 브루저, 리퍼 역할에서 대응 제작 모델을 자동 선택해야 한다(MUST).
- **FR-012**: 모델 선택은 기존 좀비 체력, 속도, 공격, 표적 우선순위, 위협 비용, 경로, 스폰 규칙을 변경하지 않아야 한다(MUST NOT).
- **FR-013**: 제작 모델은 기존 게임플레이 루트의 위치, 배율, 충돌체와 머리 판정 기준을 변경하지 않아야 한다(MUST NOT).
- **FR-014**: 제작 모델 내부의 충돌 요소는 게임플레이 충돌 판정에 참여하지 않아야 한다(MUST).
- **FR-015**: 피격, 헤드샷, 사망 및 리퍼 특수 위협 효과는 제작 모델의 모든 표시 부분에 적용되어야 한다(MUST).
- **FR-016**: 특정 역할 항목 또는 고세부 모델이 누락되면 해당 역할만 기존 절차형 외형으로 복구되어야 한다(MUST).
- **FR-017**: 저세부 모델만 누락되면 고세부 모델 하나로 정상 표시되어야 한다(MUST).
- **FR-018**: 반복 연결은 이전 표현 루트와 세부 단계 구성 요소를 남기지 않아야 한다(MUST).
- **FR-019**: 모든 제작 자산은 프로젝트 소유로 기록되고 외부 모델·텍스처 입력을 사용하지 않아야 한다(MUST).
- **FR-020**: 기존 플레이어 대상 문자열, 텔레메트리 사건 및 결정적 시뮬레이션 결과는 변경되지 않아야 한다(MUST NOT).

### Key Entities

- **제작 좀비 모델 항목(Authored Zombie Model Entry)**: 좀비 표현 역할, 자산 ID, 고세부·저세부 모델, 실루엣 서명을 연결한다.
- **좀비 제작 원본(Zombie Authoring Source)**: 세 유형 중 하나를 재생성할 수 있는 편집 가능한 원본과 제작 절차다.
- **좀비 세부 단계 쌍(Zombie Detail Pair)**: 같은 역할과 계층을 공유하는 고세부·저세부 표시 모델이다.
- **절차형 좀비 폴백(Procedural Zombie Fallback)**: 제작 모델을 불러올 수 없을 때 사용하는 기존 역할별 표현이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 처음 보는 플레이테스터의 90% 이상이 무채색 갤러리를 5초 본 뒤 러너, 브루저, 리퍼를 모두 정확히 구분한다.
- **SC-002**: 세 고세부 모델 모두 16,000개 초과 정점과 다섯 개의 사용 중인 재질 영역을 가지며, 세 저세부 모델 모두 대응 고세부 모델의 70% 미만이다.
- **SC-003**: 세 역할의 제작 모델 선택, 세부 단계 전환, 폴백 및 반복 교체 자동 검증이 모두 통과한다.
- **SC-004**: 제작 모델 적용 전후의 좀비 게임플레이 루트 충돌 범위와 머리 판정 기준 차이가 0이다.
- **SC-005**: 기존 전체 자동 검증, Windows 빌드와 독립 실행 준비 상태 확인이 모두 성공한다.
- **SC-006**: 세 유형 중 하나의 모델을 제거한 세 가지 실패 시나리오 모두에서 나머지 두 유형의 제작 모델 사용률이 100% 유지된다.

## Assumptions

- "좀비도 더 정교하게"는 현재 제공되는 러너, 브루저, 리퍼 세 유형 전체의 외형 품질을 해태 모델 수준으로 높이는 요청으로 해석한다.
- 이번 범위는 정지 기본 자세의 제작 모델과 런타임 이동 표현이며, 새로운 골격 애니메이션과 모션 캡처는 포함하지 않는다.
- 기존 캡슐 루트와 크기 설정이 게임플레이 충돌 및 헤드샷 기준의 유일한 소유자다.
- 외부 모델이나 텍스처를 채택하지 않고 프로젝트 내부에서 형상과 재질을 제작한다.
- 고어 표현은 피하고 감염 조직과 손상된 장비를 스타일화해 전투 판독성을 우선한다.
- 기존 절차형 러너, 브루저, 리퍼 표현은 삭제하지 않고 역할별 실패 폴백으로 유지한다.
