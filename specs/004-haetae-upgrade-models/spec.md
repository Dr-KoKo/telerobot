# Feature Specification: 해태 업그레이드 모델

**Feature Branch**: `004-haetae-upgrade-models`

**Created**: 2026-07-27

**Status**: Draft

**Input**: User description: "이제 업그레이드 버전의 해태 로봇도 만들어보자"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 전투 특화 형태를 즉시 구분한다 (Priority: P1)

플레이어는 해태가 근접형, 원거리형, 균형형으로 업그레이드된 뒤 이름이나 색상만 보지 않고도 전장에서 현재 역할을 즉시 구분한다.

**Why this priority**: 업그레이드는 전투 의사결정을 바꾸는 핵심 상태이므로, 모델 실루엣이 실제 역할과 일치해야 한다.

**Independent Test**: 세 업그레이드 모델을 같은 크기와 중립 조명으로 나란히 표시하고 색상을 제거한 뒤, 각 역할을 외형만으로 식별할 수 있다.

**Acceptance Scenarios**:

1. **Given** 일반형 해태가 근접형으로 업그레이드되었을 때, **When** 플레이어가 전투 거리에서 로봇을 보면, **Then** 강화된 전면 충각·뿔·어깨·앞발 장갑으로 근접형을 식별한다.
2. **Given** 일반형 해태가 원거리형으로 업그레이드되었을 때, **When** 플레이어가 전투 거리에서 로봇을 보면, **Then** 등 위의 포탑·포신·조준 센서와 가벼운 전방 실루엣으로 원거리형을 식별한다.
3. **Given** 일반형 해태가 균형형으로 업그레이드되었을 때, **When** 플레이어가 전투 거리에서 로봇을 보면, **Then** 소형 포탑과 강화 턱·앞다리가 결합된 비대칭 혼합 실루엣으로 균형형을 식별한다.

---

### User Story 2 - 기존 해태 정체성과 유닛 구분을 유지한다 (Priority: P1)

플레이어는 어떤 업그레이드 모델에서도 같은 해태 계열임을 알아보고, 1호기와 2호기를 계속 구분한다.

**Why this priority**: 특화 장비가 캐릭터 정체성과 현재 조종 대상을 가리면 기존 전투 정보가 손실된다.

**Independent Test**: 일반형과 세 업그레이드형을 함께 표시해 공통 머리·갈기·중앙 뿔·재질 언어를 확인하고, 각 형상에서 두 유닛 표식을 개별 전환한다.

**Acceptance Scenarios**:

1. **Given** 네 형태가 나란히 표시되었을 때, **When** 플레이어가 모델을 비교하면, **Then** 공통 몸체 비율과 해태 얼굴·갈기·중앙 뿔을 통해 같은 계열로 인식한다.
2. **Given** 어느 업그레이드형이 활성화되었을 때, **When** 1호기와 2호기를 번갈아 선택하면, **Then** 색상 이외의 표식 개수 차이도 유지된다.
3. **Given** 업그레이드 전환이 발생했을 때, **When** 새 모델이 표시되면, **Then** 위치·충돌 범위·공격 판정·진행 상태는 바뀌지 않는다.

---

### User Story 3 - 업그레이드 모델 실패에도 계속 플레이한다 (Priority: P2)

플레이어는 특정 고품질 모델이 누락되거나 표시할 수 없는 경우에도 기존 대체 외형으로 게임을 계속 진행한다.

**Why this priority**: 시각 자산의 문제로 전투 세션이나 업그레이드 진행이 중단되어서는 안 된다.

**Independent Test**: 세 업그레이드 모델 참조를 각각 제거한 상태에서 해당 역할을 활성화하고, 역할별 대체 외형과 기존 게임 동작이 유지되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 선택한 업그레이드 모델이 누락되었을 때, **When** 역할이 활성화되면, **Then** 해당 역할의 기존 대체 외형이 표시되고 게임은 계속된다.
2. **Given** 서로 다른 세부 수준의 모델이 제공될 때, **When** 관찰 거리가 변하면, **Then** 역할 실루엣과 유닛 표식은 유지되면서 표시 복잡도만 감소한다.

### Edge Cases

- 업그레이드 상태가 빠르게 연속 전환되어도 이전 모델이나 재질이 남지 않아야 한다.
- 한 역할의 모델만 누락되어도 다른 두 역할과 일반형 모델은 정상적으로 유지되어야 한다.
- 세부 수준이 전환되는 거리에서도 포탑, 충각, 중앙 뿔과 유닛 표식이 갑자기 사라져 역할이 바뀐 것처럼 보이지 않아야 한다.
- 파괴 또는 비활성 상태로 전환될 때 업그레이드 부품이 본체와 분리되어 남지 않아야 한다.
- 서로 다른 업그레이드를 적용한 두 해태가 동시에 존재해도 유닛 표식과 역할 실루엣이 충돌하지 않아야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 제품은 근접형, 원거리형, 균형형 각각에 고유한 완성형 3D 모델을 제공해야 한다.
- **FR-002**: 세 모델은 일반형의 몸체 비율, 해태 얼굴, 층진 갈기, 중앙 뿔, 발톱과 꼬리 구조를 공통 계보로 유지해야 한다.
- **FR-003**: 근접형은 강화된 전면 충각·쌍뿔·어깨·앞다리 장갑을 실루엣 핵심 요소로 포함해야 한다.
- **FR-004**: 원거리형은 등 위의 회전식 포탑, 명확한 포신, 조준 센서와 후방 장비 볼륨을 실루엣 핵심 요소로 포함해야 한다.
- **FR-005**: 균형형은 소형 포탑, 강화 턱, 한쪽 전방 장갑 또는 센서의 제한된 비대칭을 결합한 혼합 실루엣을 포함해야 한다.
- **FR-006**: 세 모델은 색상을 제거한 상태에서도 서로 구분되는 비색상 형태 단서를 각각 두 가지 이상 제공해야 한다.
- **FR-007**: 세 모델은 일반형과 동일한 다섯 재질 역할을 사용하고, 모든 재질 역할은 보이는 면에 실제로 사용되어야 한다.
- **FR-008**: 각 업그레이드형은 가까운 거리용과 먼 거리용의 두 세부 수준을 제공해야 하며, 먼 거리용은 가까운 거리용보다 표시 복잡도가 30% 이상 낮아야 한다.
- **FR-009**: 각 업그레이드형은 1호기와 2호기의 개별 표식을 유지해야 한다.
- **FR-010**: 업그레이드 전환은 기존 진행 상태가 지정한 역할과 표시 모델을 일치시켜야 한다.
- **FR-011**: 모델 교체는 위치, 이동, 충돌 범위, 공격 판정, 능력치, 타깃 선택과 진행 규칙을 변경하지 않아야 한다.
- **FR-012**: 특정 업그레이드 모델을 사용할 수 없을 때 해당 역할의 기존 대체 외형을 자동으로 사용해야 한다.
- **FR-013**: 세 모델은 편집 가능한 원본, 재현 가능한 제작 기록, 배포용 결과물과 동일 원본에서 만든 검토 이미지를 포함해야 한다.
- **FR-014**: 업그레이드 모델 전환과 세부 수준 전환은 이전 시각 객체나 재질 인스턴스를 누적해서는 안 된다.
- **FR-015**: 기존 플레이어 표시 문자열과 업그레이드 명칭은 변경하지 않아야 한다.

### Key Entities

- **업그레이드 모델 세트**: 근접형, 원거리형, 균형형의 가까운 거리/먼 거리 모델과 검토 이미지를 묶는 시각 자산 집합.
- **역할 시각 매핑**: 기존 업그레이드 상태를 일반형 또는 세 특화 모델과 연결하고, 누락 시 대체 외형을 선택하는 관계.
- **유닛 표식**: 모델 형태와 무관하게 1호기와 2호기를 구분하는 별도 표시 요소.
- **공통 해태 계보**: 네 형태가 공유하는 비율, 얼굴, 갈기, 중앙 뿔, 재질 역할과 관절 명세.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 중립 조명의 무채색 검토에서 5명 중 4명 이상이 세 업그레이드 역할을 5초 안에 모두 정확히 식별한다.
- **SC-002**: 세 업그레이드형 모두 가까운 거리 모델의 총 정점 수가 18,000보다 크고, 먼 거리 모델은 가까운 거리 모델의 70% 미만이다.
- **SC-003**: 세 업그레이드형 모두 정확히 다섯 재질 역할을 사용하며 빈 재질 역할이 없다.
- **SC-004**: 일반형과 세 업그레이드형 전체에서 1호기와 2호기 표식이 각각 식별 가능하다.
- **SC-005**: 각 업그레이드 모델 참조를 개별적으로 제거한 세 번의 검증에서 대체 외형이 100% 표시되고 세션 진행이 중단되지 않는다.
- **SC-006**: 전체 자동 회귀 검증, 배포 대상 빌드와 독립 실행 준비 검증이 실패 없이 완료된다.
- **SC-007**: 업그레이드 적용 전후의 게임 오브젝트 위치와 충돌 범위 비교에서 차이가 발생하지 않는다.

## Assumptions

- "업그레이드 버전"은 기존 진행 기능에 정의된 근접형, 원거리형, 균형형 세 역할을 의미한다.
- 이 기능은 시각 자산과 표시 매핑만 다루며 새로운 능력치, 공격 방식, 업그레이드 선택지나 애니메이션을 추가하지 않는다.
- 일반형의 검증된 비율, 재질 언어, 관절 계층과 절차형 대체 외형을 재사용한다.
- 업그레이드형은 동일한 골격 계열을 사용하지만 역할별 장비는 해당 몸체 부위에 함께 결합되어 표시된다.
- 고유 텍스처 제작은 이번 범위에 포함하지 않으며 재질 역할과 형상으로 역할을 구분한다.
