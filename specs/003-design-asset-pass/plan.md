## Summary

Replace the runtime-only greybox presentation with a coherent first-pass visual identity while preserving every collider, rule, route, balance value, input, string, and deterministic result. The selected direction is a stylized low-poly near-future Korean city defense: dark neutral urban surfaces, cyan/gold guardian technology, and red/magenta enemy corruption, with haetae horn/crest motifs and two non-color readability cues per important role.

The implementation adds a data-owned visual theme and asset catalog, shared URP materials, a compound low-poly visual factory that decorates stable gameplay roots, themed world landmarks, UI skinning and code-native icons, lightweight pooled VFX, and an original text-free menu backdrop. Project-owned/generated assets cover the first pass. License-clear external sources are recorded as candidates for future skeletal animation, specialist audio, fonts, and modular environment replacement; no candidate is imported without a complete source record.

## Visual Identity Summary

- **World**: charcoal asphalt/concrete, cool steel, restrained haze; Korean guardian geometry through roofline brackets, crest cuts and octagonal/taegeuk-derived rings without copying protected logos.
- **Allies**: cyan energy for systems, gold for haetae identity, orange secondary marker for unit 2, green/teal for medical support.
- **Enemies**: desaturated bodies with red corruption; runner uses forward fins, bruiser wide shoulders/armor, ripper tall blade forearms and magenta core.
- **Interaction**: charge station cyan concentric coils; safe supply green closed crate; risky supply amber open beacon; barrier cyan segmented wall.
- **Routes**: north chevron/tower, east stacked alley pylons, south tunnel arches. Shape and icon differ in addition to color.
- **UI**: dark translucent panels, clipped/octagonal corners, 2 px cyan/gold hierarchy lines, Korean sans-serif text, red reserved for imminent danger.
- **Effects**: brief directional shapes, small additive glow, no full-screen repeated flash, no opaque smoke wall.

## Runtime Integration Strategy

1. Keep each current primitive root and collider as the authoritative gameplay object.
2. Disable only the root renderer after a themed child visual is successfully built.
3. Resolve an authored model reference for the General haetae role, instantiate it below the child visual root and remap its named material slots to the shared theme.
4. Use shared materials plus `MaterialPropertyBlock` for unit identifiers rather than one material instance per object.
5. If theme or construction fails, leave the existing renderer visible and log one development warning.
6. Route all runtime color/effect lookups through `VisualThemeDefinitionAsset`.
7. Keep specialization variants addressable by presentation role; map the existing feature-002 domain enum to these role keys without adding another progression enum.
8. Keep menu background text-free; all labels remain `StringTable.asset` lookups.
9. When an authored model reference is absent or instantiation fails, build the existing procedural role through `LowPolyModelFactory` as the explicit fallback.

## Performance and Accessibility Strategy

- Use authored LOD0/LOD1 meshes for the General haetae and shared theme material instances.
- Retain Unity primitive meshes only for documented missing-asset fallback and roles not yet promoted to authored models.
- Cap child mesh part counts per common zombie and per effect.
- Use a rigid-bone robot hierarchy without runtime texture imports; do not add per-frame skinning logic.
- Cache GUI styles/icons and avoid creating them in `OnGUI`.
- Bound transient effect lifetime and maximum concurrent instances.
- Validate grayscale silhouettes and route markers without relying on hue.
- Preserve reticle contrast using a local dark backing/outline rather than global brightness.
- Capture baseline and themed Phase 3 frame timing under identical accelerated-spawn conditions.

## Validation Strategy

- **EditMode**: required catalog IDs, unique IDs, allowed state/source/license combinations, required source fields, visual role coverage, material/theme ranges, fallback presence.
- **PlayMode**: stable gameplay roots and colliders, child visual creation, fallback behavior, distinct unit part signatures, route landmark creation, menu background/UI style, no missing font glyph for required strings, bounded VFX cleanup.
- **Deterministic regression**: identical simulator result/event stream before and after because no presentation assemblies are referenced.
- **Manual screenshot review**: menu, normal battle, mixed enemy wave, all interactables, command UI, result UI, plus visual-variant gallery.
- **Accessibility**: grayscale capture and 5-second identification survey.
- **Performance**: Phase 3 max-alive comparison with frame-time percentiles and memory delta.
- **Licensing**: every included third-party file resolves to a complete source record and notice.
