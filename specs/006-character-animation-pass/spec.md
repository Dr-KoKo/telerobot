# Feature Specification: 캐릭터 전투 애니메이션 패스

**Feature Branch**: `006-character-animation-pass`

**Created**: 2026-07-28

**Status**: Implemented; manual visual acceptance pending

**Input**: User description: "테스트해보니 문제는 없어. 다음 진행해." 이전 제안에 따라 좀비 이동·공격·피격·사망과 해태 대기·이동·공격 모션을 구현한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 좀비의 행동을 움직임만으로 읽는다 (Priority: P1)

플레이어는 러너, 브루저, 리퍼가 가만히 있을 때, 이동할 때, 공격을 준비하거나 실행할 때, 피해를 받거나 쓰러질 때를 자세와 리듬만으로 구분한다. 각 유형은 같은 감염체 계열로 보이면서도 체형과 역할에 맞는 속도감과 무게감을 가진다.

**Why this priority**: 좀비의 상태를 빠르게 읽는 것은 회피, 조준, 거점 방어 우선순위 판단에 직접 영향을 주며 정교해진 모델을 실제 게임 안에서 살아 있게 만드는 가장 큰 시각 개선이다.

**Independent Test**: 음향과 상태 표시를 끈 상태에서 세 좀비 유형을 각각 대기·이동·공격·피격·사망 상태로 보여 주고 관찰자가 1초 안에 상태를 구분하게 한다.

**Acceptance Scenarios**:

1. **Given** 세 좀비가 이동 중임, **When** 같은 거리에서 관찰함, **Then** 러너는 빠르고 전방으로 기울며, 브루저는 낮고 무겁게 흔들리고, 리퍼는 긴 팔과 칼날을 절제된 리듬으로 운반한다.
2. **Given** 좀비가 공격 가능한 거리에 도달함, **When** 공격이 준비되고 피해가 적용됨, **Then** 공격 준비·타격·회복 자세가 기존 공격 시점과 일치하며 실제 피해 판정은 바뀌지 않는다.
3. **Given** 좀비가 생존 가능한 피해를 받음, **When** 피격 반응이 재생됨, **Then** 짧은 반응이 현재 행동을 알아볼 수 있게 강조하지만 이동과 공격 판정을 지연시키지 않는다.
4. **Given** 좀비의 체력이 소진됨, **When** 기존 사망 연출 시간이 진행됨, **Then** 유형에 맞는 붕괴 자세가 현재 소멸 시점 안에 끝나고 충돌 비활성화 시점은 바뀌지 않는다.

---

### User Story 2 - 해태의 전투 역할을 모션으로 구분한다 (Priority: P1)

플레이어는 해태 로봇이 대기, 이동, 근접 공격, 원거리 공격 또는 균형형 공격을 수행하는지 움직임만으로 알아본다. 해태는 기계 수호수다운 안정감과 무게를 유지하고, 업그레이드 역할에 따라 준비 자세와 반동이 달라진다.

**Why this priority**: 해태는 플레이어의 핵심 전력이며 공격 역할을 즉시 읽을 수 있어야 명령 결과와 업그레이드 선택이 시각적으로 납득된다.

**Independent Test**: 일반·근접·원거리·균형형 해태를 동일한 배경에서 대기·이동·공격 상태로 전환하고 역할별 모션과 공격 시점을 구분한다.

**Acceptance Scenarios**:

1. **Given** 해태가 목표 없이 대기함, **When** 5초간 관찰함, **Then** 작은 호흡성 기계 움직임이 반복되며 미끄러지거나 지면을 관통하지 않는다.
2. **Given** 해태가 이동 명령을 수행함, **When** 방향을 바꾸고 정지함, **Then** 보행 리듬이 이동과 함께 시작·종료되고 몸체가 진행 방향의 변화에 자연스럽게 반응한다.
3. **Given** 해태가 공격함, **When** 기존 공격 이벤트가 발생함, **Then** 근접형은 전방 충격, 원거리형은 조준과 반동, 균형형은 절제된 혼합 동작을 보이며 피해량과 재사용 대기시간은 바뀌지 않는다.
4. **Given** 두 해태가 동시에 서로 다른 행동을 수행함, **When** 화면에서 함께 관찰함, **Then** 각 개체의 모션 상태와 위상이 독립적으로 유지된다.

---

### User Story 3 - 부분 실패와 대규모 전투에서도 플레이를 유지한다 (Priority: P2)

개발자와 플레이어는 특정 모델에 기대한 관절이나 세부 구조가 없거나 화면에 많은 캐릭터가 있어도 전투가 계속되고, 보이는 모델 단계가 전환되어도 모션이 튀지 않기를 기대한다.

**Why this priority**: 애니메이션은 표현 기능이므로 부분적인 자산 문제나 성능 상황이 게임 진행과 판정을 막아서는 안 된다.

**Independent Test**: 필요한 구조 일부가 없는 대체 모델, 세부 단계 전환, 최대 전투 밀도를 각각 재현하고 게임 진행·모션 연속성·프레임 안정성을 확인한다.

**Acceptance Scenarios**:

1. **Given** 캐릭터 모델의 선택적 움직임 부위가 없음, **When** 행동 상태가 바뀜, **Then** 가능한 범위의 전체 자세 모션으로 계속 표현되고 오류가 전투를 중단하지 않는다.
2. **Given** 캐릭터의 표시 세부 단계가 전환됨, **When** 이동 또는 공격 중임, **Then** 두 표시 단계가 같은 행동 위상과 방향을 유지해 눈에 띄는 자세 점프가 없다.
3. **Given** 한 화면에 최대 예상 수의 좀비와 해태가 있음, **When** 모두 서로 다른 행동을 수행함, **Then** 입력과 전투 진행이 유지되고 모션 처리가 지속적인 성능 저하를 만들지 않는다.

### Edge Cases

- 행동 상태가 한 프레임 안에 연속 변경되면 가장 최근의 유효한 상태로 부드럽게 수렴한다.
- 피격과 공격이 겹치면 피격 강조 후 현재 공격 위상으로 복귀하며 피해 이벤트를 중복 발생시키지 않는다.
- 사망 상태에 들어간 캐릭터는 이후 이동·공격 모션으로 복귀하지 않는다.
- 일시 정지 또는 시간 배율 변경 시 모션도 게임 시간과 함께 정지하거나 비례해 진행한다.
- 모델 교체나 표현 재연결이 반복되어도 모션 처리 구성 요소가 중복되지 않는다.
- 화면 밖 또는 보이지 않는 세부 단계의 모션 계산이 화면 안 캐릭터의 성능을 불필요하게 저하하지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 러너, 브루저, 리퍼 각각에 대기, 이동, 공격 준비·타격·회복, 피격, 사망 모션을 제공해야 한다(MUST).
- **FR-002**: 세 좀비 유형의 이동 모션은 체형과 역할에 맞는 서로 다른 실루엣, 주기, 보폭감과 무게 중심을 가져야 한다(MUST).
- **FR-003**: 좀비 공격 모션의 타격 강조점은 기존 피해 적용 시점과 시각적으로 일치해야 한다(MUST).
- **FR-004**: 리퍼의 특수 공격 모션은 기존 경고와 실제 공격의 순서를 명확히 전달해야 한다(MUST).
- **FR-005**: 좀비 피격 모션은 짧은 강조 표현이어야 하며 이동, 공격, 경로, 피해 판정을 차단하거나 지연하지 않아야 한다(MUST NOT).
- **FR-006**: 좀비 사망 모션은 기존 사망 연출 시간과 충돌 비활성화 및 제거 시점을 변경하지 않아야 한다(MUST NOT).
- **FR-007**: 시스템은 일반, 근접, 원거리, 균형형 해태에 대기와 이동 모션을 제공해야 한다(MUST).
- **FR-008**: 근접, 원거리, 균형형 해태 공격은 준비 자세, 주 동작과 회복 반동이 역할별로 구분되어야 한다(MUST).
- **FR-009**: 해태 공격 모션은 기존 공격 이벤트, 피해량, 범위, 재사용 대기시간과 목표 선택을 변경하지 않아야 한다(MUST NOT).
- **FR-010**: 각 캐릭터 개체는 다른 개체와 독립적인 모션 위상과 행동 상태를 유지해야 한다(MUST).
- **FR-011**: 이동 모션의 강도는 실제 이동 여부와 속도 변화에 반응하고 정지 시 대기 상태로 자연스럽게 전환되어야 한다(MUST).
- **FR-012**: 같은 캐릭터의 모든 표시 세부 단계는 동일한 행동 상태와 모션 위상을 유지해야 한다(MUST).
- **FR-013**: 선택적 움직임 부위가 없는 모델은 오류 없이 전체 자세 또는 정적 표현으로 폴백해야 하며 전투를 계속해야 한다(MUST).
- **FR-014**: 표현 재연결과 모델 교체를 반복해도 캐릭터당 모션 처리 경로는 하나만 남아야 한다(MUST).
- **FR-015**: 모션은 게임 시간의 일시 정지와 시간 배율을 따라야 한다(MUST).
- **FR-016**: 모션 구현은 캐릭터의 게임플레이 루트 위치, 배율, 충돌체, 경로 탐색, 머리 판정 기준을 변경하지 않아야 한다(MUST NOT).
- **FR-017**: 모션 구현은 기존 체력, 속도, 공격, 배터리, 업그레이드, 스폰, 목표 우선순위와 텔레메트리 결과를 변경하지 않아야 한다(MUST NOT).
- **FR-018**: 현재 자동 검증, Windows 빌드와 실행 준비 확인은 모두 계속 통과해야 한다(MUST).
- **FR-019**: 모션 상태는 테스트가 읽을 수 있는 관찰 가능한 상태와 역할 식별자를 제공해야 한다(MUST).
- **FR-020**: 이 기능은 플레이어 캐릭터와 의료 로봇의 신규 전신 애니메이션을 추가하지 않아야 한다(MUST NOT).

### Key Entities

- **캐릭터 모션 상태(Character Motion State)**: 대기, 이동, 공격 준비·타격·회복, 피격, 사망 중 현재 표현 상태와 상태 진행도를 나타낸다.
- **모션 역할 프로필(Motion Role Profile)**: 러너, 브루저, 리퍼 및 해태 역할별 주기, 강도, 자세 특성을 정의한다.
- **모션 대상 집합(Motion Target Set)**: 한 캐릭터의 모든 표시 세부 단계에서 함께 움직여야 하는 몸체와 선택적 관절 부위를 나타낸다.
- **모션 폴백(Motion Fallback)**: 기대한 세부 구조가 없을 때도 게임플레이 루트와 판정에 영향을 주지 않고 사용할 수 있는 전체 자세 또는 정적 표현이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 처음 보는 플레이테스터의 90% 이상이 음향과 상태 표시 없이 1초 안에 좀비의 대기·이동·공격·사망 상태를 구분한다.
- **SC-002**: 처음 보는 플레이테스터의 90% 이상이 같은 색으로 표시된 러너, 브루저, 리퍼의 이동과 공격 모션을 보고 유형을 정확히 구분한다.
- **SC-003**: 해태의 근접, 원거리, 균형형 공격을 나란히 보여 주었을 때 플레이테스터의 90% 이상이 역할을 정확히 분류한다.
- **SC-004**: 자동 비교에서 모션 적용 전후 캐릭터의 게임플레이 루트 위치, 충돌 범위, 공격 결과, 경로 결과와 머리 판정 기준 차이가 0이다.
- **SC-005**: 최대 예상 전투 밀도에서 모션 기능 추가 전 대비 평균 프레임 처리 시간이 10% 이상 악화되지 않는다.
- **SC-006**: 모델 구조 누락, 표시 세부 단계 전환, 반복 재연결의 자동 실패 시나리오가 모두 통과하며 전투 중단 사례가 0건이다.
- **SC-007**: 기존 전체 자동 검증, Windows 빌드와 실행 준비 확인이 100% 통과한다.

## Assumptions

- "다음 진행"은 직전에 제안한 `006-character-animation-pass`를 승인한 것으로 해석한다.
- 이 패스는 현재 정교화된 좀비와 해태 모델을 움직이는 표현 작업이며 새 게임플레이 행동이나 공격 규칙을 추가하지 않는다.
- 모션은 현재 모델의 사용 가능한 관절 구조를 활용하고, 선택적 구조가 없는 기존 절차형 폴백에는 전체 자세 모션을 제공한다.
- 음향, 발자국 효과, 카메라 흔들림, 플레이어 캐릭터와 의료 로봇 전신 애니메이션은 이번 범위에 포함하지 않는다.
- 플레이테스트 설문 수치는 수동 후속 검증이며 자동 검증은 상태, 시점, 판정 불변성과 실패 복구를 보장한다.
